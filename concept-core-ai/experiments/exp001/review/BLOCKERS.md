# BLOCKERS

この文書の提案はすべて **PROPOSED / 未承認** である。

## B-01 成功条件を操作的に判定できない

- 人間の判断が必要な項目: 「再現可能な規則的構造」を、どの指標、比較対象、効果量、反復数で成立とみなすか。実行前に seed 数と成功判定手順を固定する必要がある。
- 理由: PCA の見た目、線形プローブ精度、距離差のどれを優先するかが未定であり、現在の記述だけでは同じ結果に対して成功・失敗の両方を主張できる。成功条件は Human の承認事項でもある。
- PROPOSED: 主判定指標、未学習モデルとの差、複数 seed における集約方法を事前登録し、PCA は補助資料に限定する。
- 利点: 結果を見た後の基準選択を防ぎ、成功判定を再現できる。
- 欠点: seed 数と統計基準を増やすほど計算量が増え、探索的な観察の自由度は下がる。
- 代替案: Experiment 001 を「判定を伴わない探索実験」と明記し、成功条件を削除して観測結果のみ報告する。ただし、現行の「成功条件」とは両立しない。

## B-02 データ生成条件が確定していない

- 人間の判断が必要な項目: RGB 基準値と変動方法、位置・大きさ・回転の範囲と分布、図形の塗り方、境界のアンチエイリアス、座標と size の定義、画面外クリッピングの可否。
- 理由: これらはデータセット条件であり、色・形の読み出しやすさを直接変える。設定可能であることだけでは、初回 run の条件は決まらない。
- PROPOSED: すべての分布を数値と単位で `spec.md` に固定し、全図形が画像内に収まる制約を設ける。三角形と四角形の回転分布も個別に明記する。
- 利点: データセットを独立に再生成でき、交絡要因を説明しやすい。
- 欠点: 人工世界の設計に人間の選択が増え、その選択への依存性が残る。
- 代替案: 変動なしの基準 run と変動ありの run を別 run として事前登録する。または候補範囲を複数条件として比較する。

## B-03 データ分割手順が確定していない

- 人間の判断が必要な項目: 9 組み合わせごとの層化の有無、生成後のサンプル単位分割か生成 seed 単位分割か、分割を決める seed、各組み合わせの端数処理。
- 理由: 80/10/10 という比率だけでは、各 split の構成や再現方法が一意にならない。分割方法は評価結果へ影響するデータセット条件である。
- PROPOSED: 各色×形の 1,000 枚を 800/100/100 に層化し、生成済み `sample_id` に対して固定 seed で一度だけ split を割り当てる。
- 利点: 各 split のクラス構成が一致し、比較が安定する。
- 欠点: 自然に生じる組み合わせ頻度の偏りは評価できず、層化そのものが人工的な制約になる。
- 代替案: 全 9,000 枚を一括で無作為分割する。または、未知の組み合わせへの一般化を別実験として組み合わせ単位で hold-out する。後者は Experiment 001 の目的変更になるため別仕様が必要である。

## B-04 Autoencoder の構造と画像表現が確定していない

- 人間の判断が必要な項目: CNN/MLP 等の構造、層数、チャネル数、活性化、正規化、latent の出力形状、入力値域、decoder の出力活性化。
- 理由: モデルの帰納バイアスと容量は、再構成と潜在構造の形成を大きく左右する。「小規模」だけでは独立実装が一致しない。
- PROPOSED: 単一の基準 architecture を層ごとの入出力 shape まで固定し、パラメータ数を記録する。最初の run では architecture 探索を行わない。
- 利点: 未学習・学習済み比較と seed 間比較の意味が明確になる。
- 欠点: 選んだ architecture 固有の否定結果になる可能性がある。
- 代替案: 事前登録した少数の architecture を別条件として比較する。ただし多重比較と計算量が増える。

## B-05 学習目的と学習手順が確定していない

- 人間の判断が必要な項目: MSE/BCE/L1 の選択、損失の集約方法、optimizer、learning rate、batch size、epoch 数、早期終了の有無、最終モデルか validation-best モデルか。
- 理由: `decisions.md` の MSE は `PROPOSED` かつ未決定である。これらはモデルの学習目的または結果を左右する実験条件であり、Codex が既定値を選べない。
- PROPOSED: 初回 baseline では単一の損失と固定 epoch を事前承認し、解析対象 checkpoint を一意にする。探索をする場合は候補範囲と選択規則を先に固定する。
- 利点: run の比較可能性が上がり、都合のよい checkpoint 選択を防げる。
- 欠点: 不適切な初期設定で学習が失敗する可能性があり、調整には新しい決定が必要になる。
- 代替案: validation loss による早期終了と best checkpoint を採用する。ただし Section 18.3 の `final.pt` との関係を明文化する必要がある。

## B-06 線形プローブの学習・評価方法が確定していない

- 人間の判断が必要な項目: probe の訓練用 split、validation の用途、正則化、ハイパーパラメータ選択、評価指標、probe 用 seed、学習済み Encoder と未学習 Encoder で同一手順を使うか。
- 理由: Section 11/18.5 は Test の latent のみを保存する一方、Section 12 は線形分類器の学習を要求する。Test 上で probe を学習・評価すると汎化性能を測れない。
- PROPOSED: Encoder を固定し、Train latent で probe を学習、Validation latent で設定選択、Test latent は最終評価に一度だけ使用する。
- 利点: データ漏洩を避け、精度を未知サンプルへの読み出し性能として解釈できる。
- 欠点: 全 split の latent 保存またはオンデマンド抽出が必要になり、成果物が増える。
- 代替案: Test latent 内で事前固定の交差検証を行う。ただし Autoencoder の Test と probe の評価集合が混ざり、解釈が複雑になる。

## B-07 距離解析の評価方法が確定していない

- 人間の判断が必要な項目: 距離尺度、latent の標準化の有無、全ペアかサンプリングか、同一サンプル対の除外、seed 間集約、統計的不確実性の扱い。
- 理由: Autoencoder の latent は座標ごとの尺度が一意でなく、尺度変換で再構成を保ったまま距離を変えられる。距離定義は評価方法そのものである。
- PROPOSED: raw Euclidean 距離だけに依存せず、事前に承認した正規化後の距離、効果量、信頼区間を併記する。
- 利点: 単なる latent scale の差を規則的構造と誤認しにくい。
- 欠点: 正規化にも仮定が入り、raw latent の幾何をそのまま測る解析ではなくなる。
- 代替案: cosine 距離、decoder 出力差に基づく距離、または k-NN の近傍組成を主解析にする。いずれも事前承認が必要である。

## B-08 Pixel baseline の必須性と内容が確定していない

- 人間の判断が必要な項目: Pixel baseline を必須にするか、入力表現、モデル、split、評価指標を何にするか。
- 理由: Section 13 は「少なくとも以下と比較する」としながら Pixel baseline を「可能であれば」としている。さらに、成功の解釈には単純な RGB 統計で説明できるかの検討が重要である。
- PROPOSED: Pixel baseline を必須とし、latent probe と同じ Train/Validation/Test 手順の raw-pixel 線形分類を最低限実施する。
- 利点: 潜在表現が入力の単純統計以上の情報を形成したかを比較しやすい。
- 欠点: raw-pixel 線形分類だけでは「単純な統計」の範囲を完全には表せず、位置ずれにも敏感である。
- 代替案: RGB 平均・分散などの明示的統計量、PCA 圧縮 pixels、または複数 baseline を使う。baseline を任意のまま残す場合は、未実施時に結論可能な範囲を狭める必要がある。
